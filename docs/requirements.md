# 需求说明

## 角色与范围
报修人是使用设备的师生，负责查看设备信息和提交报修。维护人员负责维修，通过“开始维修”和“完成维修”两个操作更新工单状态。

范围只包含上述3项功能。本实验不实现网页、数据库、账号系统和真实物联网通信，编程只实现“能否转换工单状态”的判断函数。设备清单来自 data/devices.csv 的模拟数据。

## FR-01 查看设备信息
角色：报修人。
前提：data/devices.csv 中已有设备记录。
输入：打开设备清单，可按 deviceId、name 或 location 定位设备。
正常结果：显示设备编号、设备名称和安装位置，报修人据此选择要报修的设备。
异常结果：清单为空或查询条件没有匹配到设备时，提示“无匹配设备”，不进入提交报修环节。
验收方法：查询 location 为“A101教室”的设备，检查是否返回 DEV-001、温湿度传感器、A101教室三项信息。

## FR-02 提交报修
角色：报修人。
前提：设备已列入模拟设备清单。
输入：选择设备，填写非空故障描述。
正常结果：形成一张工单，记录设备编号和故障描述，工单初始状态为PENDING。
异常结果：未选择设备或描述为空时提示补充，不创建工单。
验收方法：对DEV-001提交“传感器没有读数”，检查设备编号、描述和初始状态是否符合要求。

## FR-03 更新工单状态
角色：维护人员。
允许的转换：只有两条。
1. PENDING → PROCESSING，由维护人员执行“开始维修”触发。
2. PROCESSING → COMPLETED，由维护人员执行“完成维修”触发。

拒绝的转换：除上面两条外一律拒绝，包括
- PENDING → COMPLETED（跳过处理中，不允许直接完成）；
- COMPLETED → PROCESSING、COMPLETED → PENDING、PROCESSING → PENDING（回退）；
- PENDING → PENDING、PROCESSING → PROCESSING、COMPLETED → COMPLETED（状态不变，同样拒绝）。

正常与异常结果：合法转换时工单状态更新成功；非法转换时拒绝本次操作、工单保持原状态并提示原因。本次没有重新打开、取消工单或跳过处理中的操作。
验收方法：对状态为PENDING的工单依次尝试“完成维修”和“开始维修”，检查前者被拒绝且状态仍为PENDING、后者成功变为PROCESSING；再对PROCESSING的工单尝试转回PENDING，检查被拒绝。

## 已确认的实验规则
新工单为PENDING，仅允许PENDING转PROCESSING、PROCESSING转COMPLETED。
其他转换一律拒绝。本实验暂不实现完整报修系统，只实现状态判断函数。
