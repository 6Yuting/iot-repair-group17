# 需求说明

## 角色与范围
报修人：查看设备信息、发起报修工单；
维护人员：查看工单、修改工单处理状态。

## FR-01 查看设备信息
角色：报修人，维护人员。
前提：系统中已录入设备数据。
行为与正常结果：报修人发起查看请求，页面展示设备编号、设备名称、存放位置。
异常结果：无设备数据时，页面提示设备列表为空；指定编号不存在时提示该设备不存在。
验收方法：进入设备列表页面，能够读取csv内全部设备信息。

## FR-02 提交报修
角色：报修人。
前提：设备已列入模拟设备清单。
输入：选择设备编号、填写故障描述。
正常结果：系统生成工单，工单状态初始化为PENDING，保存工单信息。
异常结果：未选设备或者故障描述为空，系统拦截提交并提示补充信息，不生成工单。
验收方法：选定设备填写故障描述提交，可查询到新建PENDING工单；空描述提交无法建单。

## FR-03 更新工单状态
角色：维护人员。
允许的转换：PENDING → PROCESSING；PROCESSING → COMPLETED。
拒绝的转换：PENDING直接转为COMPLETED、COMPLETED反向回退、同状态重复修改。
正常与异常结果：合法状态流转时工单状态更新成功；非法流转弹出提示，状态保持不变。
验收方法：PENDING工单可改为PROCESSING；PENDING直接改COMPLETED操作被阻止。

## 已确认的实验规则
新工单为PENDING，仅允许PENDING转PROCESSING、PROCESSING转COMPLETED。
其他转换一律拒绝。本实验暂不实现完整报修系统，只实现状态判断函数。
